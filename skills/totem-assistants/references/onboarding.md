# New-team onboarding

Read this only for an authorized request to provision a genuinely new client team.

preview_apply_agent_system_intent provisions a new team and refuses an existing one. Use reviewed client evidence, the required business profile and current schema. Preserve established country, brand, artifact language and business choices. Ask only for unresolved material facts. Staff authority governs provisioning and commercial/billing state.

Default onboarding creates exactly one Chat assistant and one Native Voice assistant with shareable pages. Add Draft Helpers or regression tests only when requested. By default use tests_mode: none and regression_tests: []. The onboarding exception publishes through publish_without_tests after structural/provider checks. Even explicitly authored tests are stored for later validation; they have not run and are not green. Executing paid tests needs an explicit originating human request to run them; onboarding, saved Auto, authored cases, or a review contract do not grant it.

Accepted work is queued. Follow get_agent_system_review_status with the original handle until terminal evidence, then read back the intended artifacts and safe links. Structural provisioning proves neither commercial go-live nor real telephone acceptance. Never duplicate an uncertain job, invent a team ID or construct a public URL.
